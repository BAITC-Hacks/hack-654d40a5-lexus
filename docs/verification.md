# Проверка MVP

Дата: 23 сентября 2026. Среда проверки: macOS ARM64 + Docker Desktop; PostgreSQL и production image запускаются контейнерами.

## Выполненные проверки

- `go test -race ./server`: формула и снятие подтверждений, неизменяемость опубликованных версий, публикация короткой потребности с нулём, уведомления, ограничения ввода/URL, локальный AI contract, субтитры.
- TypeScript typecheck и production Vite build.
- `scripts/smoke.py`: 22 сквозных API-проверок на отдельной базе, включая чужое редактирование, устаревшую запись, видимость нулевой задачи, старый отклик, повторный отзыв, XP и план.
- Повторный API smoke в отдельном Docker Compose проекте, с чистой базой и **без .env / API-ключей**.
- Браузер: 0 → отклик → 100 → v2 → сравнение → выбор → подтверждённый этап → сдача → отзыв. Ошибок JavaScript в сценарии не обнаружено.
- Актуальный русский UI и ширины 320, 390, 768, 1440 px. Проверка отсутствия горизонтальной прокрутки; старое сохранённое предпочтение языка не переключает текущую версию.
- Клавиатурный skip link и axe: каталог на русском, регистрация, админ-панель, языковое предупреждение, команды, тарифы, задача, редактор, мастерская. Итоговый прогон: 0 выявленных нарушений проверяемых автоматических правил. Автоматическая проверка не равна сертификации WCAG.
- Реальный OpenAI Responses: 3 уточняющих вопроса, неизвестный контакт оставлен пустым.
- Реальные TTS/STT с настроенным ElevenLabs: короткие примеры RU / KK / EN синтезированы и распознаны обратно. Текст совпадает по смыслу, возвращается на обязательную пользовательскую проверку.
- Docker video pipeline: отдельный pilot, подтверждение, полный MP4, H.264, 1280×720, 45 секунд. Варианты без голоса и с реальной озвучкой ElevenLabs собраны, кадр просмотрен. Проверено окончание титров вместе с речью, отдельно от времени для чтения финального кадра. Сценарий индивидуален для опубликованной задачи; paid LLM для рендера не вызывается.

## Что проверять вручную перед защитой

- Реальный микрофон и выбранный браузер (доступ к устройству требует разрешения самого браузера).
- Качество произношения и распознавания конкретных RU/KK/EN записей; наличие языка в провайдере не гарантирует качество каждого акцента и записи.
- Прохождение со скринридером VoiceOver/NVDA реальным пользователем.
- Текущий баланс и доступность внешних API. В отсутствие API показать обозначенный локальный помощник.

## Ограничения

- Почта/пароль и управление тарифом работают; настоящая оплата, SMTP и восстановление пароля ещё не подключены.
- Системный TTS зависит от установленных голосов. Произвольное аудио без API не распознаётся.
- Текущий интерфейс русский. Иностранные слова допустимы; выраженное расхождение языка требует подтверждения. Тексты задач и отзывов не переводятся скрыто; эвристика не гарантирует точное определение каждого языка.
- Субтитры делятся по тексту; тайминг приблизительный, без forced alignment.
- MVP использует один JSONB-агрегат и один worker. Для масштаба нужна миграция на нормализованные таблицы и очередь с lease.
- Счётчик платных API-вызовов защищает текущий процесс демо и обнуляется при перезапуске; не является биллинговым ledger.
- Рейтинг означает подтверждённую заполненность, не гарантию достоверности бизнеса и не оценку красоты текста.
- `anything2explainer` требует разрешения автора для коммерческой эксплуатации toolkit. Remotion лицензируется отдельно.

## Проверки второго этапа

- 11 Go unit-тестов с race detector: прежние доменные инварианты плюс мягкий языковой аудит, обратимый штраф и защита от подмены языка вложения и отсутствие внутренних подробностей в ошибке 500.
- Playwright: регистрация и повторный вход; выбор роли после создания аккаунта; запрет роли admin в регистрации; отсутствие старого демовхода; невозможность самостоятельно выдать себе Pro; администратор выдаёт и отзывает Pro.
- Одиночный вопрос, отдельное поле, возврат к сохранённому ответу, прогресс и просмотр ответов.
- Загрузка обложки, приватность до публикации, запрет чужого coverId, неизменяемая опубликованная обложка при изменении черновика.
- Технические термины не вызывают предупреждения. Иностранный текст можно подтвердить; исправление снимает предупреждение. Публикация иностранных материалов без согласия отвергается сервером; явное согласие даёт 95 вместо 100, исправление и повторное подтверждение данных восстанавливают 100.
- Файлы не доступны постороннему заказчику; вложение отклика доступно соответствующему владельцу задачи. HTML и файл с поддельной PDF-сигнатурой отвергаются. Старые опубликованные вложения сохраняются в истории.
- В отдельном Docker с настоящими API: английский TTS → STT распознан как `eng`, предупреждение true; русский → `rus`, предупреждение false. OpenAI вернул три вопроса на русском. Сгенерирована JPEG-обложка, повтор вернул тот же ID из кэша.
- В Docker проверено извлечение и предупреждение для английского текста из PDF и DOCX. API-ключи и тестовые материалы не попадали в основную базу.

Браузерный сквозной сценарий с настоящим входом также завершён: 0 → отклик → 100 → новая версия → уведомление → выбор команды → этап → сдача → отзыв. В сценарии 0 ошибок JavaScript. Окончательные команды проверок — в README.


## Финальная проверка Docker и обработки ошибок

- 13 браузерных тестов прошли: предыдущие сценарии плюс HTTP 500 с HTML вместо JSON и обрыв сети. Русское сообщение содержит действие для восстановления; для 500 показан ID запроса. После восстановления каталог открывается.
- На чистом Docker Compose-проекте без `.env` повторно прошли все 22 API-проверки (`finalScore=100`, `teamXPDelta=200`).
- Реальное отключение PostgreSQL только в изолированном тестовом проекте: `/api/health` вернул HTTP 500 с общей ошибкой и совпадающим `X-Request-ID`. SQL-диагностика осталась в серверном логе. После запуска БД health восстановился без изменения кода и сброса базы.
- Вход администратора → перезапуск app → сессия действительна; выход → повтор ранее выданного cookie больше не авторизует запрос.
- Production image: 30-секундное видео без голоса/API → `preview_ready` → явное согласование → `ready`. Финальный MP4 скачан, размер 2 881 638 байт. Рендер использует локальные компоненты, а не платную генерацию видео.
- README сверен с п. 5.4.15 / 5.6 Положения, PDF-инструкцией участникам и §9–11 ТЗ. Все локальные Markdown-ссылки в README и docs разрешаются в существующие файлы.
