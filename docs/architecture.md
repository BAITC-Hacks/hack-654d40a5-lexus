# Реализованная архитектура MVP

Этот документ описывает работающий код. Более ранний файл `hackalem-manual/analysis/architecture-and-pipeline.md` содержит целевую архитектуру и идеи развития, а не перечень уже поставленных компонентов.

## Сервисы и состояние

Docker Compose запускает PostgreSQL 17 и приложение. В контейнере приложения находятся Go API, собранный React frontend и Node/Remotion renderer с Chromium/FFmpeg. Go раздаёт frontend и медиа с одного origin. Отдельные Redis, Kafka, object storage и SaaS для запуска не нужны.

PostgreSQL хранит `app_state(id=1, body JSONB, updated_at)`. В агрегате: пользователи, задачи, команды, предложения, уведомления, медиа и анализ изменений. `SELECT … FOR UPDATE` сериализует запись, а клиентский `revision` запрещает потерянные обновления. При изменении схема поля расширяется совместимо через JSON; seed вставляется только в пустую базу. При росте нагрузки следующий шаг — нормализованные таблицы и независимая очередь. Горизонтальный запуск нескольких workers в этой версии не предусмотрен.

## Жизненный цикл задачи

1. `POST /api/challenges` создаёт личный черновик. Поля не подтверждены.
2. `POST /api/ai` возвращает структурированный проект карточки и минимум три вопроса. В локальном режиме сохраняется только исходная потребность; недостающие факты не синтезируются.
3. `POST /api/challenges/:id` обновляет поля, снимает устаревшие подтверждения и принимает явный список `confirm`.
4. Рейтинг складывается из критериев, чьи непустые поля совпадают с подтверждёнными SHA-256.
5. `POST /api/challenges/:id/publish` требует актуальный `revision`, подтверждённую потребность и `previewApproved=true`. Полнота 100 не требуется.
6. Публикация сохраняет неизменяемый снимок. Для каждой команды, уже откликнувшейся, создаётся одно уведомление об изменениях. Частный черновик не подменяет публичный снимок.
7. `POST /api/changes` сравнивает две соседние опубликованные версии. OpenAI выдаёт краткое влияние на план; без провайдера доступен явно обозначенный локальный checklist. Ответ кэшируется на `(challenge, version, locale)`, конкурентные обращения объединяются mutex. Это совет, не изменение предложения или назначения.

## Команды и доверие

Предложение содержит ID версии. После обновления ТЗ команда явно подтверждает актуальность своего подхода. Принятие устаревшего предложения, новый этап, сдача и отзыв по неактуальным условиям не проходят серверную проверку.

Заказчик вручную выбирает `pending → accepted/rejected`; несколько принятых предложений допустимы. Только выбранная команда отправляет результат. Только владелец задачи оценивает `accepted` с отправленным результатом и завершает его. Повторный отзыв и повторное начисление XP запрещены. Средняя оценка, количество завершений и XP имеют разные значения и показываются отдельно.

## Аудио

`MediaRecorder` либо upload создают запрос multipart до 20 МБ. Сервер принимает ограниченный список аудиоформатов. ElevenLabs Scribe v2 используется при наличии его ключа; иначе OpenAI Whisper. Транскрипт всегда появляется в редактируемом диалоге, и только после подтверждения попадает в поле. Произвольная фраза в аудио никогда не является командой публикации.

Озвучивание работает через Eleven v3 / OpenAI TTS, без автозапуска. При отсутствии API возможен системный TTS браузера с явно указанным ограничением доступных голосов. Поддержка клавиатуры и скринридерных имён не зависит от платного плана.

## Видео и расход

1. Исходник — опубликованная версия, ID которой фиксируется навсегда.
2. Пользователь проверяет/редактирует сценарий из её полей, выбирает RU/KK/EN, длительность и озвучивание.
3. Подтверждает сценарий и раскадровку. Сервер создаёт `queued` job.
4. Worker сохраняет безопасный JSON manifest и один раз генерирует/кэширует голос при необходимости. Не принимает JSX, shell-команды или внешние пути от пользователя.
5. Remotion рендерит первые `min(30, duration)` секунд. Статус: `preview_ready`.
6. Пользователь смотрит реальное пробное видео и подтверждает полный рендер. Если задача уже изменилась, эта операция возвращает 409.
7. `queued_final → rendering → ready`; выход — H.264 MP4, VTT, неизменяемый номер версии. Финальный рендер не вызывает LLM/TTS повторно.

Сцены используют dot-field-компонент `anything2explainer`, белые контуры, фиолетовые акценты, спокойное появление, безопасные зоны субтитров и progress bar. Короткий адаптированный процесс не запускает дорогую multi-agent генерацию фильма заново для каждого заказа. Ограничения коммерческой лицензии toolkit сохранены в `renderer/ANYTHING2EXPLAINER-LICENSE`.

Очередь живёт в PostgreSQL, обрабатывается одним процессом последовательно. Долгие внешние вызовы и рендер не удерживают транзакцию. Перезапуск отмечает прерванный рендер ошибкой; пользователь может повторить его. Превью доступно только владельцу; финальная версия — читателям опубликованной карточки. Временные manifest/аудиофайлы не раздаются маршрутом `/media`.

## Безопасность и границы

- Серверный выбор роли и проверки владения; cookie HttpOnly, SameSite Strict. Демо-профили не являются промышленной аутентификацией.
- JSON body, текстовые поля, файлы, количество медиа и внешние вызовы ограничены.
- Origin проверяется на запись; ссылки прототипов принимаются только HTTP(S), без credentials.
- CSP, запрет embedding и sniffing; React экранирует текст.
- Секреты в `.env`, не в браузере, логах промптов или образе.
- `.env` и пользовательские prompt-логи исключены из Git и Docker build context.
- API-ошибки показываются явно; локальный помощник не выдаётся за OpenAI. Сбой анализа изменений оставляет работоспособным сравнение версий.
- Модель получает только предоставленные данные и инструкцию не добавлять неизвестные факты. Последняя проверка содержания всегда человеческая.
- Нет реального эквайринга, production-auth, постоянного spend ledger, организации multi-tenant и горизонтального worker pool.
- Тайминг субтитров рассчитывается по длине фрагментов. Это доступные текстовые титры, но не принудительное фонетическое выравнивание.
